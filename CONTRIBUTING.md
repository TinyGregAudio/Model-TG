# Contributing to Model-TG

Thanks for helping. Model-TG is hand-written ColdFire assembly patched into a
closed firmware, so a few rules keep it safe to build and flash.

## Ground rules

- **Never commit Elektron firmware**, not even a fragment: no `.syx`, no
  extracted sections, no disassembly or decompiler output. `.gitignore` covers
  the build outputs. Short stock byte sequences that a patch asserts (as
  `build.py` does) are fine: they are what makes a wrong OS version fail
  safely.
- **One feature or fix per pull request.**
- **Test on hardware** anything that changes audio, the UI or files, and say
  in the PR what you checked. CI can only assemble the code.
- **Update [docs/USER_GUIDE.md](docs/USER_GUIDE.md)** for anything a player
  will see or press.

## Getting set up

Follow [docs/BUILD.md](docs/BUILD.md). While you work, the quick check is:

```sh
python3 build.py --assemble-only
```

It assembles and links `src/` and runs the build's self-checks, with no stock
firmware needed. A full build (`--stock`) also checks every stock byte a patch
replaces.

## Where things are

| path | what |
|---|---|
| `src/model_tg.s` | nearly everything: the Sampler, modes, pages, effects |
| `src/phase1.s`, `src/track_table.s` | boot hook, machine catalogue, trampoline |
| `src/*.inc` | tables and strings (`granular_tables.inc` is generated by `tools/gen_granular_tables.py`) |
| `build.py` | links the blob, applies and asserts every patch, packs the `.syx` |
| `tweaks/` | vendored third-party tweaks |
| `docs/INTERNALS.md` | how it works, and firmware facts worth knowing |

## Conventions the code relies on

- **Assert before you patch.** Every write into the stock area in `build.py`
  checks the exact stock bytes first.
- **Nothing of ours below `0x401ab750`.** Our code lives in one blob in
  filesystem cache blocks; the build reserves as few as it needs (currently 5
  of 16). If a feature needs another block, raise the limit in `build.py` and
  say so in the PR.
- **Replay what you overwrite.** A hook that replaces stock instructions runs
  them itself, then returns to the stock code.
- **Keep the audio path cheap.** Everything in `sampler_render`, `rtg_audio`,
  `mfx_*` and the mixer hooks runs every 32 samples. Say in the PR what your
  change costs on the System page (**Device Config > System**, second page).
- **The screen's y runs from the bottom.** See
  [INTERNALS.md](docs/INTERNALS.md#useful-firmware-facts).
- **Assembler gotchas** (GNU as, `-march=cfv4e`): `cmpi` only takes a data
  register; there is no `mulsl` with an immediate or absolute operand; `moveml`
  has no predecrement mode; byte branches fail when a function grows, so use
  `.w`, and use `jsr`/`jmp` beyond ±32 KB. The build checks that every 16-bit
  branch lands on a label.
- **Comment the why.** The existing comments record which stock routine a hook
  wraps and what was verified on hardware. Keep doing that: it is the only
  map anyone has.

## Reporting bugs

Use the bug report template: the commit you built, the build's last lines
(including the sha256), the buttons you pressed, and whether stock OS 1.13
does the same.
